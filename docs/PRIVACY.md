# 隱私說明

看板只讀取這台電腦的資料，沒有帳號、雲端上傳或遙測；唯一的網路存取是選用的更新檢查。
這份文件說明看板讀取與保存哪些資料，以及發布內容如何檢查。各檔案的位置見
[使用說明](USAGE.md#檔案位置)。一般使用不會自動截圖或上傳資料。

## 網路存取：更新檢查

唯一的網路存取是選用的更新檢查（「設定 → 更新 → 自動檢查更新」，預設開啟，可以關閉）：
- 自動檢查：看板啟動 15 秒後與之後每 6 小時看一次，但距離上次成功的檢查超過 24 小時才送出
  一個 HTTPS 請求到 api.github.com，讀取本專案公開的 Releases 清單。關閉後完全不連線；
  「立即檢查」只在你按下時連線一次。
- 安裝更新（只有 .deb，按「安裝更新」才進行）：從 github.com 與它轉址到的 GitHub 下載主機
  （*.githubusercontent.com，例如 objects.githubusercontent.com、release-assets.githubusercontent.com）
  下載 SHA256SUMS、SHA256SUMS.sig 與 .deb，放在 XDG_RUNTIME_DIR 底下的私人暫存目錄，安裝後刪除。
- 送出的只有請求本身：網址、User-Agent（system-device-monitor/版本號）與 Accept 標頭；
  沒有 cookie、帳號、裝置識別碼、設定或任何讀值。GitHub 與網路路徑上的系統一定看得到你的 IP
  與請求時間，這是任何連線都無法避免的。只連 HTTPS，主機不在上述名單（含每一次轉址）就停止；
  會使用系統的代理伺服器設定（https_proxy 等環境變數）。
- 只在 XDG 狀態目錄的 update-state.json 記錄上次成功檢查的時間與通知過的版本號，不記錄其他內容，
  也不寫進日誌。模擬測試（--smoke-test）與示範模式（--preview）完全不連網路。

## 本機保存的資料

- 耗電歷史（時間、整機瓦數、不斷電系統電量與是否改用電池）只存在本機 XDG 資料目錄的 history.json
  （資料夾權限 0700），不上傳，也不屬於發布內容。筆電的歷史紀錄只有時間、電量、整機耗電、
  是否接電與是否充電中。
- 由 UPower 補上的電量也存在同一個 history.json：只有時間、電量、接電狀態，以及哪些時段已經補過
  （系列只寫成「pct」「ups_pct」）。補上時只向 UPower 讀取裝置清單、裝置類型、是否為系統電源與
  電量紀錄，不讀序號或型號；裝置路徑（藍牙裝置的路徑可能含有硬體位址）只在讀取當下存在記憶體，
  不寫進檔案、日誌或 --dump。示範模式與模擬測試不讀取。
- 智慧充電（筆電）只在這台電腦保存資料，不連網路、不上傳：
  - 排程存在 XDG 資料目錄的 charging-plan.json（0600）：完成時間、星期、目標與保養上限、原本的上限、
    睡眠策略與這一輪的狀態（何時開始、何時充好、通知過沒有）；無法解讀時另存 .bak 備份。
  - 紀錄存在 XDG 狀態目錄的 charging-plan.log（0600，超過 256 KB 時只留後半）：時間、電量與上限的
    百分比、所需分鐘數、狀態與寫入結果；不記錄電池名稱、序號、帳號或位置。
  - 開啟「允許無人時自動調整」時，/etc/polkit-1/rules.d/49-system-device-monitor.rules 含有你的
    帳號名稱與 uid（只有 root 與 polkitd 能讀；uid 只用來發現帳號被同名的新帳號取代）；喚醒小程式在
    /run 記下排定的時間（root 0600，重開機就消失）。系統日誌只記錄小程式的動作與結果（例如 set ok），
    不記錄時間、數值或帳號。
  - 示範模式與模擬測試的排程與紀錄只在記憶體，不寫入任何檔案；--charging-plan-status 只讀不寫。
- 周邊設備的通知門檻存在 preferences.json，鍵是 `HMAC-SHA256(salt, 設備識別碼)` 的前 16 碼，
  檔案中沒有識別碼本身。salt（peripheral_key_salt，32 個十六進位字元）是每次安裝隨機產生的，
  在第一次設定周邊門檻時才產生，與門檻存在同一個檔案：不同電腦的鍵無法互相比對，
  但能讀這個檔案的人仍可用自己已知的藍牙位址算出對應的鍵。第一版沒有 salt 的鍵，
  在第一次設定時換成新鍵；目前看不到的設備無法換，直接丟掉（門檻回到預設的 20%）。
- 「我的照片」只存在本機 XDG 資料目錄（~/.local/share/system-device-monitor/companion-photo.png，
  權限 0600），不上傳，也不屬於發布內容。選照片時會依拍攝方向轉正、裁成正方形、縮成 512 × 512，
  再重新編碼成只含畫面資料的 PNG：拍攝時間、地點、相機型號、色彩描述檔等照片資訊一律不保留。
  示範模式與模擬測試不讀這張照片，截圖只會出現內建的貓咪大頭照。
- 桌面寵物的位置（兩個整數）存在 XDG 狀態目錄的 pet.json；換色的程式圖示寫在使用者的圖示主題，
  寫入的檔案名稱與雜湊記在 XDG 資料目錄的 app-icon.json，只用來在改回預設顏色時刪除自己的檔案。

## 讀取的硬體資訊

- 機型只讀取主機板廠商與產品名稱，不讀序號或 UUID；不斷電系統只讀取 apcaccess 的狀態、數值與型號。
- 筆電電池只讀取 /sys/class/power_supply 中列出的屬性（電量、能量、電壓、電流、溫度、
  循環次數、充電門檻、廠商與型號等），絕不讀 serial_number，也不讀含序號的 uevent；
  UPower 只逐一讀取剩餘時間、充滿時間等需要的屬性，不讀序號或裝置路徑；補上歷史時另外列出
  UPower 的裝置，只讀類型、是否為系統電源與電量紀錄（見上一節）。
- 系統監控頁只讀取需要的數值，而且只在頁面顯示時讀取，都不寫入檔案或日誌：
  - 各 App 的用量只讀程序群組目錄名稱（App 代號）、累計 CPU 時間與記憶體，
    不讀任何程序的命令列、環境變數或開啟的檔案；名稱與圖示取自已安裝的桌面檔。
  - 磁碟 SMART 透過系統的磁碟服務逐一讀取健康度、溫度、通電時間與讀寫量等屬性，
    不讀序號、WWN 或其他識別碼；磁碟服務的物件路徑只在記憶體中使用。
  - 主要網路介面的 IPv4 只顯示在視窗裡，不寫入日誌、模擬測試結果或 --dump。
- Solaar 完整 CLI 輸出只在查詢程序及解析期間存在於記憶體，不寫入看板日誌、快取檔或發布產物。
  看板只保留電量、時間及本機匹配所需路徑。Solaar 自己的個人設定也不屬於專案發布內容。

## 通知

通知只交給本機桌面的通知服務（工作階段匯流排），不經過網路，看板也不保存通知紀錄。
內容只有百分比、瓦數、分鐘數與設備名稱；設備名稱中像 MAC、IPv4、IPv6 位址或序號
（8 個以上、同時有字母與數字的英數字詞）的部分改成 x，所以有些型號名稱也會被遮住；
不含藍牙位址或裝置路徑。通知失敗時日誌只記錄錯誤類型，不記錄通知內容或設備名稱。

## 管理員功能

- 管理員 CPU 功耗取樣預設關閉。開啟後讀取 RAPL 能量計數器；這些計數器可能被用來推測同一台電腦上
  其他程式的運算（旁路攻擊，例如 PLATYPUS），所以系統預設只讓 root 讀取。緩解方式：
  只有開啟它的帳號能連到取樣服務（socket 0600 並確認連線者身分），但這個帳號底下任何沒有被沙箱
  隔離的程式都讀得到同樣的數值；服務只提供全部連線共用的 1 秒視窗平均、四捨五入到 0.1 W，
  不提供原始計數器；刻度的相位在服務啟動時決定，這些程式可以等服務閒置結束後重新啟動它來換一個
  相位，但每個數字仍是整整 1 秒的平均；看板只在「電源」頁顯示時連線，不需要時請關閉。
  1 秒、0.1 W 的平均只看得出持續的耗電變化（例如是否有重度工作），看不出單一運算的差異，
  原因見 [SECURITY.md](SECURITY.md#rapl-旁路)。CPU 功耗只存在記憶體，
  不寫入歷史檔、日誌或 --dump。APU 校正只在 XDG 狀態目錄記錄是否已確認
  （cpu-calibration.json：格式、倍率與是否確認），不含任何讀值。
- 充電上限：看板以一般權限讀取電池的充電門檻與保留的狀態檔；寫入由管理員小程式進行，系統日誌只記錄
  動作名稱與結果（例如「set ok」），不記錄電池名稱或數值。開啟「開機與喚醒後保留」時，
  /var/lib/system-device-monitor/charge-limit.json（所有人可讀）只記錄電池名稱（例如 BAT0）與上限。
  偵測會同時設定充電門檻的程式時，只讀 /etc/tlp.conf 與 /etc/tlp.d 的充電門檻設定、以 systemctl
  查詢 tlp.service 是否作用中、比對 /proc 中有沒有名為 asusd 的程序（只看程序名稱），以及 UPower 的
  兩個充電門檻屬性；結果只顯示在視窗中，不寫入檔案或日誌。

詳情見 [SECURITY.md](SECURITY.md)。

## 診斷與回報問題

- --dump 只輸出硬體種類摘要（項目名稱、類型、可讀的屬性名稱、是否有充電門檻等），
  不含讀值、序號、UUID、MAC 位址、IP、主機名稱或家目錄與掛載路徑，也不寫任何檔案。
- --preview 示範模式只用記憶體中的示範資料，不讀寫設定、歷史或裝置別名。
- 本機主動啟用 --capture 後，截圖可能含私人設備名稱與掛載路徑。
- 回報問題只提供去識別化的摘要，勿直接附上原始日誌、設定或截圖。

## 發布內容

公開內容僅限來源清單中的程式、圖示、文件、CI 及合成測試。
執行期檔案由另一份明確清單控制。

以下資料不進入 Git、來源壓縮包或 .deb：
- 密碼、SMTP 憑證、API key、token、SSH 私鑰、憑證檔。
- 個人信箱、主機名稱、裝置序號、MAC 位址、私人掛載路徑。
- 個人設定、裝置別名、實機資料輸出、日誌、截圖、備份。
- 編輯器或其他工具的工作紀錄、家目錄內容、既有 UPS 通知服務設定。

make privacy 檢查公開清單、檔名與常見私人資料格式，
並使用 Gitleaks 掃描內容。掃描器只輸出類別與檔名，
Gitleaks 使用 redact 隱藏命中值。這些自動檢查須搭配人工檢查，
不能保證找到所有形式的私人資訊。

隨程式發布的圖檔（assets/ 底下的 PNG）必須列在公開清單中，而且只能有畫面需要的區塊；
make privacy 會拒絕含文字、拍攝資訊、時間或色彩描述檔等附屬區塊的 PNG，
其他位置的 PNG 與 JPEG 仍一律不准發布。

首次 commit 前檢查暫存的公開檔案；push 前檢查所有將推送的 Git 紀錄，
以及實際解包的發行產物。發現敏感內容就先移除，重新建置與檢查；
不能以忽略規則掩蓋真實敏感資料。

Git 提交使用 GitHub noreply 信箱，MIT 署名使用公開帳號。
GitHub 登入使用系統憑證儲存，驗證憑證不寫進專案或遠端 URL。
