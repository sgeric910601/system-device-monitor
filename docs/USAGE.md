# 使用、更新與移除

安裝、系統需求與移除步驟的摘要見 [README](../README.md)；這份文件是各功能的詳細說明。

**筆電功能（電池、充電上限、智慧充電、精準喚醒）都只以合成的 /sys 資料、假的 logind 與私人匯流排
驗證，尚未在真正的筆電上測試。** 遇到問題請依「[回報筆電問題（--dump）](#回報筆電問題--dump)」附上輸出。

## 桌面與背景執行

從應用程式選單啟動看板。關閉視窗會隱藏到頂端列，
再次啟動會開啟同一個視窗，不產生第二個監看實例。
頂端列的「退出」會結束程序。

原始碼安裝可明確控制登入啟動：

    /usr/bin/python3 install.py --autostart on
    /usr/bin/python3 install.py --autostart off

預設 preserve：首次安裝啟用，以後保留使用者選擇。
.deb 不在安裝過程修改任何人的家目錄；第一次啟動時才建立該使用者設定。
桌面啟動項目使用絕對路徑，不依賴互動式 shell 的 PATH 或 Conda。

## 命令列選項

| 選項 | 用途 | 詳細說明 |
|---|---|---|
| （沒有選項） | 開啟看板；已經在執行時開啟同一個視窗 | 上一節 |
| --background | 只在頂端列執行、不開視窗（登入自啟使用） | 上一節 |
| --version | 印出版本後結束（不載入 GTK） | — |
| --preview 情境 | 示範模式：以記憶體中的示範資料開啟視窗 | [示範模式](#示範模式--preview) |
| --dump | 印出硬體摘要（JSON）後結束 | [回報筆電問題](#回報筆電問題--dump) |
| --charging-plan-status | 唯讀印出智慧充電的狀態（JSON）後結束 | [紀錄與查詢](#紀錄與查詢) |
| --test-notification | 請正在執行的看板送出一則測試通知後結束 | [通知](#通知) |
| --smoke-test --output-dir 資料夾 | 本機診斷，約 25 秒後結束 | [本機診斷](#本機診斷) |

--version、--dump、--charging-plan-status、--test-notification、--smoke-test 與 --help 的結果一定印在
終端機；其他指令（包括打錯的選項）從終端機執行時也印在終端機。登入自啟（--background）與從應用程式
選單啟動時，看板的訊息寫進 ~/.cache/system-device-monitor/app.log。選項必須寫完整，不接受縮寫。
從終端機啟動後要關掉終端機、讓看板留在背景時，請加上 --background：訊息才會寫進 app.log。
--test-notification 與 --charging-plan-status 只能單獨使用，--preview 不能搭配 --background。

## 視窗與設定

- 主視窗左側是頁面側欄：電源、系統總覽、CPU／GPU、記憶體、磁碟、網路、連線設備。
  視窗寬度小於 640 px 時側欄收起，改用標題列左上角的頁面選單（標題列的副標題顯示目前的頁面）；
  480 px 寬的視窗也能正常顯示，卡片會自動改成一欄。
- 關閉視窗時記住目前的頁面，下次開啟從那一頁開始；這個狀態存在
  ~/.local/state/system-device-monitor/state.json，不是設定。
- 標題列的齒輪按鈕開啟設定視窗，左側分類同樣在窄視窗時收起：
  - 一般：登入自動啟動、監控範圍、更新頻率與省電模式。
  - 頂端列：分開顯示或合併成一個、耗電（筆電為電池）項目的顯示格式、要顯示的項目。
  - 監控模組：系統監控總開關與 CPU／GPU、記憶體、磁碟、網路四個模組。
  - 顯示項目：電力流向細項與詳細資訊欄位要不要顯示，以及「全部顯示」。
  - 通知：低電量與充飽提醒（有電池時）、不斷電系統提醒（有不斷電系統時）、傳送測試通知（見「通知」）。
  - 周邊設備：目前連線、回報電量的每台設備的低電量通知門檻，以及「全部設為」。
  - 夥伴：充電夥伴的外觀（有預覽）、大頭照的眼睛會不會眨、我的照片（選擇與移除）與動畫說明。
  - 桌面寵物：開關、浮在視窗上或放在桌布上、大小、大頭照的眼睛跟著滑鼠游標。
  - 外觀：程式圖示的顏色（有預覽）。
  - 管理員功能：管理員元件的安裝狀態與選用的 CPU 功耗取樣（見下方「管理員功能」）。
  - 更新：目前版本、自動檢查與通知、立即檢查、更新內容與「安裝更新」（見下方「更新」）。
  - 關於：版本與本機說明文件的位置。
- 所有變更立即套用、不需要重新啟動；連續調整時在最後一次之後 0.5 秒才寫入設定檔。
  舊版的五個頂端列項目（CPU、CPU 溫度、記憶體、GPU、網速）仍寫在 settings.json，
  其他設定寫在同目錄的 preferences.json。preferences.json 由較新版本建立時，
  新設定的控制項會停用並在視窗上方說明原因（舊版項目仍可變更）。
  三個檔案（settings.json、preferences.json、登入自啟）各自寫入；寫入失敗時這次執行仍會套用，
  失敗的項目在 15 秒、60 秒後重試，再失敗就在這次執行放棄（只記錄一次警告，視窗上方說明原因）。
  settings.json 無法解析時，第一次覆寫前先另存 settings-<時間>.json.bak（不覆寫既有備份），
  備份失敗就不覆寫。
- 第一次啟動（settings.json 原本不存在）時詢問監控範圍：「只看電源」只在頂端列顯示電量，
  四個系統監控模組都不取樣；「電源＋系統監控」為預設（直接關閉視窗也是這個）。
  桌機的說法是「只看耗電」與「耗電＋系統監控」。之後可在「設定 → 一般 → 監控範圍」更改。

## 頂端列

- 分開顯示：耗電（筆電為電池）、CPU、CPU 溫度、RAM、GPU、網路各一個圖示，依此順序由左到右，
  可在「設定 → 頂端列 → 頂端列項目」個別關閉；全部關閉時只留程式圖示，選單仍可打開。
- 合併成一個：只留一個圖示，勾選的項目依上面的順序以「｜」串成一行，例如
  「297 W｜CPU 12%｜54°C｜RAM 34%｜GPU 30%｜↓340K ↑12K」；筆電的時間放在括號裡，
  例如「82%（3:25）｜CPU 12%」。頂端列太擠時使用。切換模式不會多出新的圖示。
- 選單：每個項目一行（點一下開啟它的頁面，不論是否顯示在頂端列；關閉的監控模組不列出）、
  設備電量、電源模式、開啟看板、設定…、退出。「設備電量」每台有回報電量的設備一行，不斷電系統
  另有一行；不斷電系統的詳細資料在看板中，不另外建立頂端列圖示。
- 耗電項目的顯示格式（參考 macOS 版）：
  - 圖示＋百分比「82%」；只有圖示；只有百分比（充電中為「⚡82%」，GNOME 仍會保留圖示的位置）。
  - 圖示＋剩餘時間「3:25」：用電池時是剩餘時間、充電時是充滿（或到上限）的時間，
    沒有時間時顯示百分比。
  - 圖示內百分比＋剩餘時間：百分比畫在電池裡，旁邊是時間；沒有時間時顯示「—」，
    已充飽、接電未充電與已達上限分別寫「已充飽」「接電」「已達上限」。
  - 桌機一律顯示整機瓦數（例如「297 W」），只有圖示時不顯示瓦數。
- 電池圖示依電量填滿：正在放電且電量低於低電量門檻（預設 20%）時為紅色，接著電源時為綠色；
  充電中疊上閃電，接電未充電、已充飽與已達上限疊上插頭。桌機是插頭圖示，
  不斷電系統改用電池時改成橘色的不斷電系統圖示並畫出電量，電量低時為紅色。
- 圖示是程式畫的 SVG，存在 $XDG_RUNTIME_DIR/system-device-monitor/icons/
  （資料夾 0700、檔案 0600，登出就清除），內容改變時才在 power-a.svg 與 power-b.svg 之間輪替
  （GNOME 依檔名快取圖示）。寫不出檔案時改用系統圖示主題的電池圖示，
  同樣的內容 60 秒後才再試一次。

## 更新頻率與省電模式

「設定 → 一般 → 更新頻率」可選每秒、每 2 秒（預設）、每 5 秒、每 10 秒，變更後立即重新排程：

| 項目 | 間隔 |
|---|---|
| CPU、記憶體、網速（頂端列、選單與總覽） | 更新頻率 |
| 總覽的磁碟讀寫、風扇、其他感測器、磁碟與網路卡溫度 | 只在總覽顯示時（顯示時立即更新一次） |
| 溫度、不斷電系統、筆電電池、耗電拆解 | 更新頻率，但最快每 5 秒 |
| nvidia-smi 常駐程序的輸出 | 更新頻率，但最快每 2 秒（間隔改變時才重新啟動） |
| 頁面顯示時的詳細取樣（各核心、App 排行、記憶體組成等） | 更新頻率，但最快每 2 秒 |
| 設備重新確認 | 更新頻率，但最快每 5 秒 |
| 耗電歷史 | 每分鐘記錄一次 |

省電模式：更新頻率至少每 2 秒，「電源」頁的電力流向改為靜態圖（不播放動畫）。
勾選「只在使用電池時（筆電電池或不斷電系統改用電池）啟用」時，接著外部電源就暫時恢復一般模式；
筆電看變壓器有沒有接著（讀不到時視為接著），桌機看不斷電系統有沒有改用電池，
狀態改變時立即重新計算。

視窗關閉或最小化時只更新頂端列與選單，各頁在視窗再次顯示時才重畫。
電力流向動畫在沒有任何瓦數，或視窗被其他視窗完全遮住時也會改成靜態圖。

系統監控模組（設定 → 監控模組）關閉時立即停止它的取樣，並隱藏它的頁面、總覽卡片與頂端列項目：
CPU／GPU 包含 CPU 使用率、CPU 溫度、GPU 使用率與其他感測器；記憶體；磁碟包含讀寫速率與磁碟清單；
網路包含網速與網路介面。四個都關閉時，一般層完全不排程。顯示卡的耗電屬於「電源」頁，
所以 nvidia-smi 仍會執行。

## 電源模式

電源模式（省電／平衡／效能）來自系統的電源模式服務（power-profiles-daemon），
與 GNOME 快速設定裡的電源模式相同，作用中的本機使用者切換時不需要密碼。
- 頂端列選單的「電源模式」與「電源」頁的「電源模式」卡片只列出服務回報的模式；
  沒有這個服務時兩者都不顯示。
- 切換以非同步 D-Bus 呼叫進行（逾時 1.8 秒）；失敗時記錄錯誤並把選項恢復成實際的模式。
  在 GNOME 快速設定切換時，選單與「電源」頁也會跟著更新。

## 電源頁與耗電歷史

「電源」頁的整機耗電 = 不斷電系統負載百分比 × 額定功率，是不斷電系統的總輸出，
包含螢幕、喇叭等所有插在上面的設備，不只是電腦本身。負載以百分比回報，
所以數字會以約額定功率 1% 為一格跳動。

- 拆解：已知元件（NVIDIA 顯示卡、AMD 獨立顯示卡，以及開啟管理員 CPU 功耗取樣時的 CPU）各自列出，
  「其他」＝整機減去已知元件，含螢幕與電源損耗。CPU 底下再分「核心」與「插槽其餘」
  （只在清單中縮排顯示，不重複計入）；CPU 讀值超過慢速間隔的 3 倍（預設 15 秒）沒有更新就不列入。
- AMD 內建顯示（處理器內的顯示晶片）的功耗讀值（PPT）代表整顆處理器，單位沒有文件可查。
  CPU 功耗取樣開啟期間，看板每累積 30 筆就比對一次 PPT ÷ 1000 與 RAPL 的比例，中位數在 ±25% 內
  才記為「已確認」（存在 ~/.local/state/system-device-monitor/cpu-calibration.json）。
  之後關閉取樣時，只有已確認的校正才會把 PPT 顯示成「CPU（插槽功耗估算）」，未確認時一律不顯示。
- 沒有不斷電系統時，只能顯示已知元件合計，並註明無法取得整機耗電。
- 改由不斷電系統電池供電時，標題改成橘色並顯示剩餘分鐘數；電池電量低時改為紅色。
- 3 分鐘平均為指數移動平均（時間常數 180 秒）。

耗電歷史每分鐘記錄一筆，保留 7 天，存在 XDG 資料目錄
（預設 ~/.local/share/system-device-monitor/history.json，資料夾權限 0700，
檔案與備份權限 0600）。每累積 15 筆與退出時寫入；寫入失敗時隔 15、30、60 分鐘重試，
連續 5 次失敗就在該次執行停止寫入。檔案無法解讀或超過 20 MB 時，先原樣另存為
history-<時間>.json.bak（不覆寫既有備份）再從空白開始；
無法讀取或無法備份時，該次執行不寫入歷史，原檔保持不變。
時鐘落後時不刪任何紀錄；時鐘大幅往前跳、會刪到最近一天的紀錄時，先另存一份備份。

補上歷史的空白：看板啟動時，以及從睡眠喚醒後，會檢查最近 7 天內有沒有超過 15 分鐘沒有紀錄的時段
（包括剛安裝之前）；有的話，向系統電源服務 UPower 讀一次它自己的電量紀錄，把那段時間補上，在圖上
畫成較淡的虛線（滑鼠移到圖上或圖下方的「系統紀錄補上」可看說明）。筆電補電池電量，桌機補不斷電
系統電量（看板有在記錄時）；耗電沒有對應的系統紀錄，不補。
- 看板自己的紀錄絕不會被覆寫，今日回顧與拔電時間也只用看板自己的紀錄；電腦睡眠期間系統同樣沒有
  紀錄，這段仍是空白。
- 每段空白只補一次。UPower 沒有執行或回應太慢時，5 分鐘、15 分鐘後再試，同一次執行最多三次；
  UPower 在看板最新一筆前後 30 分鐘內的電量與那一筆相差超過 10 個百分點時（可能是另一台裝置），
  這次執行不補；那段時間 UPower 沒有紀錄時不比較。
- 補上的資料存在 history.json 的 imported 欄位，格式版本不變：舊版看板照樣讀得懂這個檔案
  （存檔時會丟掉這一段，之後再補一次）。
- 示範模式（--preview）與模擬測試（--smoke-test）不會讀取。
- 這個功能只以私人匯流排上的假的 UPower 與一台桌機的不斷電系統（唯讀）驗證，
  尚未在真正的筆電上測試。

頂端列「耗電」指示器可在「設定 → 頂端列 → 頂端列項目 → 整機耗電」關閉；
這個選項存在 preferences.json，不影響舊版的 settings.json。

「電源」頁的其他內容：
- 電力流向：流帶上的虛線依瓦數往右流動（最多每秒 15 格）；只在頁面顯示、視窗沒有最小化、
  省電模式沒有生效時播放，其他時候改為在流帶末端畫箭頭的靜態圖，不留任何計時器。
  「設定 → 顯示項目」可以隱藏顯示卡（含 NVIDIA、AMD）、處理器與「其他」，整機瓦數不變。
- 電源模式：見下方「電源模式」。
- 耗電排行：CPU 用量最高的 5 個 App（同一個 App 的子程序合併）。拆解中有 CPU 時，
  以「CPU 功耗 × 該 App 佔所有 App CPU 時間的比例」估算瓦數並註明「依 CPU 佔比估算」；
  沒有 CPU 功耗時依 CPU 使用率排序並註明原因。只在「電源」頁顯示時取樣。

## 管理員元件

需要 root 才能做的事交給幾個很小的管理員小程式，看板本身一律以一般使用者執行。元件都是選用的，
開啟程式或設定視窗時不會要求密碼。威脅模型與每個元件的限制見 [SECURITY.md](SECURITY.md)。

| 小程式 | 功能 | 授權 |
|---|---|---|
| sdm-cpu-power（與取樣服務 sdm-cpu-power-service） | [CPU 功耗取樣](#cpu-功耗取樣)：開關讀取 RAPL 的系統服務 | 開啟、關閉每次都要管理員密碼 |
| sdm-charge-limit | [充電上限](#充電上限)：寫入電池的充電門檻、開關「開機與喚醒後保留」 | 智慧充電自動調整上限：沒有授權時要密碼（約 5 分鐘內不必重輸）；允許無人時自動調整之後免密碼。手動拖動滑桿與開關保留一律要密碼（約 5 分鐘內不必重輸） |
| sdm-wake | [精準喚醒](#智慧充電)：設定、取消 RTC 喚醒鬧鐘 | 設定、取消喚醒：沒有授權時要密碼（約 5 分鐘內不必重輸）；允許無人時自動調整之後免密碼 |
| sdm-unattended | [允許無人時自動調整](#允許無人時自動調整)：寫入或刪除只給你的 polkit 規則 | 開啟、關閉每次都要管理員密碼 |
| sdm-update（只有 .deb） | [一鍵更新](#更新)：以 apt-get 安裝驗證過簽章的新版本 | 每次都要管理員密碼 |

允許無人時自動調整之後，只有智慧充電自動寫入的充電上限，以及喚醒的設定、取消在你登入並使用這台電腦時
免密碼；手動拖動滑桿（會一併寫入「開機與喚醒後保留」的設定）與其他動作照常需要密碼。授權視窗由 pkexec 顯示。

安裝：
- .deb：已經包含全部元件，安裝時不啟用任何服務。小程式在 /usr/libexec/system-device-monitor。
- 原始碼資料夾：在資料夾裡執行（會跳出管理員密碼視窗或在終端機詢問密碼）：

      /usr/bin/python3 -B install.py --system-components install

  一次安裝 CPU 功耗取樣、充電上限、精準喚醒與無人授權四種元件（一鍵更新只隨 .deb 提供，原始碼資料夾
  以 git 更新）。只安裝已提交（git HEAD）的版本；相關檔案有未提交的修改時會拒絕，授權前會先顯示要
  安裝的提交。原始碼資料夾、.git 與上層目錄必須只有你（或 root）能寫入。已安裝 .deb 時會拒絕。
  檔案安裝到 /usr/local/libexec/system-device-monitor、/usr/local/share/polkit-1/actions 與
  /etc/systemd/system（名稱含 -local-）；下面各節的指令在原始碼安裝時都把 /usr/libexec 換成
  /usr/local/libexec，單元名稱加上 -local-。git pull 之後「設定 → 管理員功能」顯示需要重新安裝時，
  再執行一次同一個指令（CPU 功耗取樣原本開著時會自動重新啟動 socket）。

狀態：「設定 → 管理員功能」顯示元件是已安裝（.deb）、已安裝（原始碼）或未安裝，以及充電上限元件的
狀態；原始碼資料夾還沒安裝時顯示上面的指令，可按「複製」貼到終端機。版本不符時顯示
「需要重新安裝管理員元件」：原始碼安裝重新執行上面的指令，.deb 重新安裝套件。

移除：
- 原始碼：`/usr/bin/python3 -B install.py --system-components remove`。先撤銷無人授權的規則、
  取消排定的喚醒並停用服務，再刪除所有元件與原始碼版保留的充電上限。已安裝 .deb 時會拒絕
  （兩者共用無人授權的規則與喚醒紀錄）：要改用套件時，先執行這個指令再安裝套件；已經兩者都裝了時，
  先 sudo apt remove system-device-monitor、再執行這個指令，之後重新安裝套件。
- .deb：sudo apt remove system-device-monitor 停用服務、移除所有元件，撤銷無人授權的規則、取消排定的
  喚醒，並刪除保留的充電上限（/var/lib/system-device-monitor/charge-limit.json）；
  sudo apt purge system-device-monitor 另外刪除一鍵更新的執行鎖，並再確認一次這些檔案都已刪除。

### CPU 功耗取樣

Linux 的 CPU 功耗來自 RAPL 能量計數器，只有 root 能讀。這個選用功能安裝一個很小的系統服務：
它從不以 root 執行（systemd 臨時配發的帳號、沒有任何能力），只有 root 能讀的計數器由 systemd
唯讀開好交給它；只回答開啟它的使用者，提供固定 1 秒視窗的平均、四捨五入到 0.1 W。
RAPL 可能被用於旁路攻擊，多人共用的電腦不建議開啟（見 [SECURITY.md](SECURITY.md#rapl-旁路)）。

- 開啟「設定 → 管理員功能 → CPU 功耗取樣」會跳出管理員授權視窗；授權後 socket 只允許你的帳號連線。
  取消授權或密碼錯誤時選項自動恢復，並在「上次的錯誤」說明原因。關閉時同樣需要授權。
- 開啟程式時只確認元件與版本，不會要求密碼；選項開著但服務沒有為你開啟（例如元件被移除），
  會直接關閉選項並說明。
- 開啟後只在「電源」頁顯示時連線，每個更新間隔讀一次；離開頁面就斷線，服務閒置 30 秒後自行結束。
- 不經由看板操作時（例如遠端維護），也可以直接執行：

      pkexec /usr/libexec/system-device-monitor/sdm-cpu-power enable
      pkexec /usr/libexec/system-device-monitor/sdm-cpu-power status
      pkexec /usr/libexec/system-device-monitor/sdm-cpu-power disable
      systemctl status system-device-monitor-cpu-power.socket

## 充電夥伴

「電源」頁的瓦數旁（筆電在電量標題旁，充電上限滑桿在同一欄的標題下方）有一隻充電夥伴：
- 表情：筆電充電中躺在發光的充電墊上（綠色）、充飽或到達上限很開心、電量低於低電量門檻
  （10% 以下為紅色）或接電時供電不足會擔心，其他時候打瞌睡（頭上飄 Z）。
  桌機在不斷電系統改用電池時擔心、負載高（不斷電系統負載 70% 以上，沒有不斷電系統時
  已知元件合計 400 W 以上）時很忙，其他時候打瞌睡；電量條顯示不斷電系統的電量。
- 外觀：貓咪（會呼吸）、電池夥伴（有表情的電池，會眨眼）、電量條（充電時有光點流動）、
  貓咪大頭照（眼睛會眨，開啟「跟著滑鼠游標」時眼珠會看向游標）與我的照片。
  點一下夥伴換下一個外觀（還沒選照片時跳過「我的照片」），按右鍵可以直接選或打開「夥伴」設定。
- 我的照片：在「設定 → 夥伴 → 我的照片」選一張圖片，會依拍攝方向轉正、從中間裁成正方形、
  縮成 512 × 512，重新存成不含任何照片資訊（拍攝時間、地點、相機等）的 PNG，
  只放在 ~/.local/share/system-device-monitor/companion-photo.png（權限 0600）。
  「移除照片」會刪除這個檔案，正在使用時改回貓咪大頭照。
- 動畫只在夥伴看得到時播放（主視窗沒有隱藏、最小化或被完全遮住），每秒最多 12 格；
  省電模式生效時改成靜態圖，不留任何計時器。眼睛跟著游標時，看得到才每秒讀 12 次游標位置，
  眼珠移動得夠多才重畫。

## 桌面寵物

在「設定 → 桌面寵物」開啟（預設關閉）。寵物是沒有邊框的透明小視窗，不出現在工作列與
視窗切換，每個工作區都看得到；外觀與「夥伴」相同。
- 位置：「浮在視窗上」保持在最上層，「放在桌布上」保持在最下層（其他視窗會蓋住牠）。
  拖曳可以移動，放開後至少留 48 px 在螢幕的工作區裡（多螢幕都算，不會整隻躲到頂端列或 Dock 底下），
  拖曳或改大小之後的位置記在
  ~/.local/state/system-device-monitor/pet.json；外接螢幕拔掉後回到主螢幕右下角。
- 大小：小（75%）、標準（100%，邊長 176 px）、大（150%）、特大（200%）；改大小時腳底不動。
- 滑鼠移過去：想像框顯示電量與狀態，例如「62%・充電中，36 分鐘後到 80%」；
  桌機顯示「整機 288 W・市電」，不斷電系統改用電池時加一行剩餘時間。
- 點一下：對話框說下一句話（心情、今天用掉與補回的電量、電池健康度與循環次數、整機耗電；
  桌機為心情、整機耗電、不斷電系統電量與負載；沒有資料的那句不說），4 秒後收起。
- 左右來回摸牠（1.5 秒內換 3 次方向）：冒愛心、說呼嚕呼嚕，之後 1.2 秒內不重複。
- 連點兩下打開看板的「電源」頁；按右鍵有選單：打開看板、浮在視窗上／放在桌布上、大小、外觀、
  桌面寵物設定與關閉桌面寵物。
- 點在寵物透明的地方等於點在下面的東西，對話框也不會擋住滑鼠。
- 動畫在看板視窗隱藏時也會播放（寵物仍看得到），只有省電模式時停止。
- 需要 X11。Wayland 工作階段中寵物會是有標題列的一般小視窗：不能放在桌布上或固定在最上層，
  不記位置，對話框的位置也可能不準。

## 系統監控頁（CPU／GPU、記憶體、磁碟、網路）

「系統總覽」之後的四個頁面。總覽頁的卡片點一下就會開啟對應的頁面
（CPU、CPU 溫度與顯示卡 →「CPU／GPU」，記憶體 →「記憶體」，網路 →「網路」，
磁碟與儲存空間 →「磁碟」，不斷電系統 →「電源」）。

取樣分兩層：
- 一直取樣：頂端列與選單需要的 CPU、記憶體、網速、CPU 溫度、顯示卡與耗電
  （依更新頻率；關閉的監控模組不取樣，見「更新頻率與省電模式」）。
  總覽才用得到的磁碟讀寫、風扇、其他感測器、磁碟與網路卡溫度只在總覽顯示時讀取。
- 只在頁面顯示時取樣：各核心、平均負載與時脈、溫度分組與風扇、各 App 的用量、
  記憶體組成與壓力、磁碟讀寫與 SMART、主要網路介面與 IPv4。
  切換頁面、關閉或最小化視窗後就停止，沒有任何計時器留著；換頁前送出的取樣結果會被丟棄。
- 磁碟清單（lsblk）在總覽或磁碟頁開著時每 30 秒更新，其他時候每 5 分鐘。

各頁的 2 分鐘曲線只保留最近 120 秒（最多 120 點）；頁面隱藏期間不取樣，所以重新打開時從新的資料開始。

「CPU／GPU」頁
- 使用率分「使用者」（user＋nice）與「系統」（system＋irq＋softirq＋steal）；計數器倒退
  （例如睡眠喚醒）時那一次不計算。
- App 排行：100% 代表用滿一個核心，旁邊另列佔全機的比例。每個 App 依 systemd 的程序群組
  計算，同一個 App 的多個視窗、子程序與不同啟動方式（指到同一個桌面檔）合併；
  名稱與圖示取自 App 的桌面檔，找不到時顯示代號（10 分鐘後再查一次）。
  兩個不同的 App 名稱相同時，名稱後面加上代號的最後一段區分，例如「Google Chrome（Chrome）」。GNOME Shell 與 Xorg 合併為「GNOME 桌面」，系統服務合併為「系統服務」。
  第一次取樣只建立基準，所以剛打開這頁的 2 秒內顯示「計算中…」。
- 風扇與溫度：CPU、顯示卡、儲存裝置、網路卡與其他，各顯示「平均（最高）」；
  0 °C 以下或 125 °C 以上視為讀取失敗。某個感測器暫時讀不到時沿用最近 2 分鐘內的讀值，
  平均才不會跳動。

「記憶體」頁
- 已使用＝總量−可用（MemAvailable），與總覽頁、頂端列相同。
- 組成：App（AnonPages）、共享（Shmem）、核心（SUnreclaim＋KernelStack＋PageTables）、
  快取（Cached＋Buffers＋SReclaimable−Shmem）、其他（核心的其他用途）、空閒（MemFree），
  合計等於總量；「可用」包含可以立即釋放的快取，另外顯示。
- 記憶體壓力：有程序等待記憶體的時間（近 10 秒）達 10%，或可用少於 10% 時為「偏高」（橘色）；
  所有程序都停住的時間達 5%，或可用少於 5% 時為「嚴重」（紅色）。
- 有 zswap 時另外顯示壓縮後與壓縮前的大小。

「磁碟」頁
- 內建與外接（USB、SD 讀卡機、可移除或熱插拔）的磁碟都列出，型號會去掉控制字元。
- 健康度：NVMe＝100%−已用壽命（≥ 70% 綠色、≥ 30% 橘色、其他紅色）；
  硬碟回報嚴重警告或備用區塊低於門檻時顯示「異常，建議立即備份」。
  SATA 硬碟依 SMART 的判定與壞軌數。SMART 還沒更新過時顯示「SMART 尚未更新」，
  多數 USB 外接盒不轉送 SMART，顯示「SMART 不支援」。
- 通電時間超過 48 小時時加上約幾天，例如「2306 小時（約 96 天）」。媒體錯誤只在大於 0 時顯示。
- SMART 來自系統的磁碟服務（UDisks2），只讀取屬性、不要求密碼；屬性每分鐘、
  NVMe 壽命資料每 10 分鐘讀一次，任何一次呼叫逾時（1.8 秒）就略過該次，30 秒後再試。
- 開機以來的累計讀寫來自 /proc/diskstats；出廠以來的讀寫量來自 SMART。

「網路」頁
- 主要介面＝預設路由中 metric 最低的介面；換介面時速率與曲線重新開始。
- IPv4 以系統呼叫讀取（不執行外部命令），每 30 秒或換介面時更新；讀不到位址時（例如還在取得
  DHCP）5 秒後再試。IPv4 只顯示在視窗裡。
- 「開機以來」是介面建立以來的累計流量；虛擬介面（容器、VPN 等）列在「其他連線中的介面」。

數字格式：系統監控頁的容量與速率以 1000 進位（例如「494 GB」「1.2 MB/s」），
記憶體以 1024 進位但寫成 GB（例如「5.5 GB」）；總覽頁與頂端列沿用原本的 KiB／MiB。

## 筆電電池

有內建電池的電腦（筆電）會自動改用電池版面；桌機維持上面的整機耗電版面。
筆電功能只以合成資料驗證（見本文件開頭），遇到問題請依「回報筆電問題」附上 --dump 輸出。

資料來源：
- 電池與變壓器：/sys/class/power_supply。系統電池＝類型 Battery、scope 不是 Device
  （滑鼠等周邊不算）；名稱不限，多顆電池的能量與功率相加，電量＝目前能量合計 ÷ 滿充合計。
  只讀取需要的屬性，從不讀序號。
- 系統預估：UPower 的剩餘時間與充滿時間。UPower 還在估算時顯示「計算中…」，
  充滿時間不馬上改用直線推算（80% 以上充電會變慢，直線推算太樂觀）。
  有些驅動永遠不給時間：UPower 持續 2 分鐘都是 0 時，充滿時間改用近 3 分鐘平均推算，
  並標示為約略值（例如「約 36 分鐘後充滿」），「系統預估」欄則改顯示「—」。
- 電源模式：電源模式服務（power-profiles-daemon）目前的模式（省電／平衡／效能）。

畫面內容：
- 標題：電量、狀態（放電中／充電中／接電・未充電／已充飽／已達上限）與
  「還能用 3 小時 25 分」「36 分鐘後充滿」「36 分鐘後到 80%」等時間。
- 時間卡片：用電池時列出到 0% 與到 10% 的時間，分「系統預估」與「依近 3 分鐘平均」兩欄，
  以及這次已使用電池多久；充電時列出充到上限或充滿的時間與平均充電速率。
  近 3 分鐘平均的充電與放電分開計算，狀態一改變就重新開始；開始充電後頭 60 秒不納入平均
  （看板啟動時已在充電則直接採用）。
- 狀態顯示會穩定 10 秒：接著電源時狀態要持續 10 秒才切換，插拔電源立即反映；
  沒有充電上限時，充到 100% 後維持「已充飽」直到低於 98%。
- 電力流向：變壓器 → 系統 → 電池（充電中）、電池 → 系統（用電池），
  接電但電池一起供電時兩邊都有箭頭。Linux 量不到變壓器的實際輸入瓦數，
  接電時整機耗電顯示「—」。USB-C PD 回報的電壓與電流是協商的契約（可用上限），
  變壓器節點只顯示「協商 45 W」，不拿來推算整機耗電。
- 接著電源但電池仍在放電超過 30 秒，標示為供電不足並顯示剩餘時間。
- 今日電量回顧：今天用掉、補回、淨變化、接電次數、使用電池總時間與最長一次；
  依每分鐘的歷史紀錄計算，看板沒在執行的時段（兩筆紀錄間隔超過 30 分鐘的部分）不列入。
- 詳細資訊（18 項，讀不到的項目不顯示）：電池電壓、電流、功率、系統耗電、系統預估、溫度、
  健康度與容量推算（滿充 ÷ 設計容量）、循環次數、電池狀況、剩餘／滿充／設計容量（Wh 與 mAh）、
  電源模式、變壓器（協商與額定瓦數）、充電上限、變壓器電壓與電流（USB-C PD 的協商值）。
  有充電上限時上限顯示在時間卡片；電池可以調整充電上限時（滑桿顯示）不重複列出「充電上限」欄位。
- 充電上限可以在電源頁調整，見下一節「充電上限」。
- 插拔電源時立即重新讀取，並在 1、3、6 秒後再讀一次（插拔通知可能比電池資料早到）。

筆電的歷史紀錄每分鐘一筆：電量、整機耗電（只有用電池時有值，接電時留空）、是否接電、是否充電中。
看板沒有記錄的時段（例如剛安裝之前）由 UPower 自己的電量紀錄補上，畫成較淡的虛線
（見上方「電源頁與耗電歷史」）。
頂端列「耗電」在筆電上顯示電量（例如「82%」）與依電量畫的電池圖示（見上方「頂端列」），
選單第一行例如「電池：82%・還能用 3 小時 25 分」。

## 充電上限

電池支援充電上限時（/sys/class/power_supply/<電池>/charge_control_end_threshold，例如 ThinkPad、
ASUS、Framework 等），「電源」頁電量標題下方會出現「充電上限」滑桿。

- 滑桿每一格是一個上限：80%、85%、90%、95% 與 100%（不限制）。拖動時右邊顯示選到的值，
  放開滑桿或停 0.6 秒才寫入（連續調整只寫最後一次），鍵盤的方向鍵也可以調整。
- 寫入需要管理員授權（polkit 視窗）；授權後約 5 分鐘內，同一個看板再次調整不必重新輸入。
  「允許無人時自動調整」只讓智慧充電的自動調整免密碼，手動拖動滑桿照常要授權。
  開啟程式時只讀取目前的上限，不會要求密碼。
- 狀態列：「套用中…」→「已套用」；沒有套用時顯示「未套用：原因」（取消授權、逾時、
  讀回的值不同等），滑桿回到實際的值。寫入後會再讀回確認（最多 3 次、間隔 0.3 秒）。
- 有「起點」（charge_control_start_threshold，例如 ThinkPad）的電池：上限要降到目前的起點
  以下時，會先把起點改成上限 − 5，再寫上限；起點原本就比較低時不動它。
- 有些機型只接受固定幾個值（例如部分 ASUS 只接受 60、80、100）：讀回的值不同時顯示
  「這顆電池不接受 85%，目前是 80%；可以改選 80%」，並把不接受的值從滑桿移除（這次執行有效）。
- 「開機與喚醒後保留」：有些韌體在開機或從睡眠喚醒時會把門檻改回預設值。開啟後，你設定的上限
  記在 /var/lib/system-device-monitor/charge-limit.json（原始碼安裝為 charge-limit-local.json，
  只有電池名稱與上限），並啟用 system-device-monitor-charge-limit.service，開機與每次喚醒後
  重新套用；關閉時刪除這個檔案並停用服務。只保留你自己設定的值；開關一樣需要管理員授權。
  開關只有在這個檔案存在、而且服務已啟用時才顯示為開啟（以一般權限查詢 systemctl is-enabled）；
  兩者不一致（例如服務被手動停用）時顯示「保留設定未生效」，重新開啟這個開關即可修復。
- 與其他程式衝突：TLP（設定了 START_CHARGE_THRESH／STOP_CHARGE_THRESH）、asusd（asusctl）
  與系統的「保護電池健康」（UPower 1.90.5 以後的充電門檻）也會設定充電門檻，並在開機、喚醒或
  插拔電源時套回自己的值。偵測到時滑桿下方顯示提醒與處理方式；仍然可以調整，但值可能被改回去。
  請只用一個工具管理充電門檻。
- 需要管理員元件（見[管理員元件](#管理員元件)）：缺少時滑桿停用，並顯示「開啟「設定 → 管理員功能」」
  連結；那裡也列出充電上限元件的狀態。

不經由看板操作時也可以直接執行（.deb 的路徑；原始碼安裝見[管理員元件](#管理員元件)）：

    pkexec /usr/libexec/system-device-monitor/sdm-charge-limit set BAT0 80
    pkexec /usr/libexec/system-device-monitor/sdm-charge-limit set BAT0 80 --persist on
    pkexec /usr/libexec/system-device-monitor/sdm-charge-limit status
    systemctl status system-device-monitor-charge-limit.service

上限只接受 50–100 的整數（100＝不限制）；起點不能指定，只在需要時自動調整（見上方）。
沒有 --persist 時不改變保留的狀態。結束碼：0 成功、2 參數錯誤、3 失敗或沒有套用、4 沒有權限。
同一時間只會執行一個（看板、命令列與開機後的重新套用共用一把鎖）；另一個正在進行時最多等 10 秒，
之後以「busy」結束，看板顯示「另一個充電上限的調整正在進行，請稍後再試」。
同一顆電池兩次 set 至少要相隔 10 秒，太快時以「rate-limited」結束；看板會自己等滿 10 秒再寫入
（這段時間狀態列顯示「套用中…」），所以連續調整時第二次會晚一點套用。所有電池合計一小時最多
寫入 30 次（保護電池的控制晶片），超過時以「hourly-limit」結束，看板顯示「這一小時內已調整
充電上限 30 次…請稍後再試」；正常使用不會碰到。喚醒小程式也一樣：一小時最多 set 30 次，取消不受限。

## 智慧充電

筆電（有可調整充電上限的電池）的電源頁，充電上限滑桿下方有「智慧充電」那一列：在你要用電腦之前
充好，平常把充電上限維持在保養上限，延長電池壽命。桌機不顯示。

- 建立排程：按「設定…」開啟編輯視窗。
  - 單次：選日期（今天起 7 天）與時間；每週：選星期與時間（例如上班日 08:00）。
  - 完成目標：「原本的上限」或 50–100% 的選項；保養上限：等待時維持的上限（不會高於目標）。
  - 下方即時預估：「需要約 1 小時 48 分，會在 05:57 開始」，或來不及時「最多約 88%」。
    充電中用目前的平均充電速度，否則用最近 7 天電量歷史的速度，都沒有時以每小時 20% 估算；
    80% 以上充電會變慢，這一段的時間乘上 1.8，再另外預留 15 分鐘。
  - 按「開始」（排程進行中為「改成這個排程」）。同一時間只有一個排程；取代排程時沿用第一次記下的
    原本上限。
- 運作方式：等待時把上限維持在保養上限（電量已經比較高時維持在目前電量進位到 5%，不先放電），
  到了開始時間把上限提高到目標，讓系統自己充；達到目標後：
  - 單次排程：拔掉電源、或完成時間過了 2 小時，就把上限還原成原本的值並結束。
  - 每週排程：換到下一次，拔電不會結束；只有取消時才還原。
  - 「原本的上限」是建立排程時的上限；開啟了「開機與喚醒後保留」時是保留的值。智慧充電的寫入
    一律不改變保留的值，所以重新開機後套回的永遠是你自己設定的上限。
  - 驅動只接受部分上限時（滑桿的選項會因為驅動拒絕某些值而變少）：保養上限向下取（不高於你選的）、
    提高時的上限向上取（一定充得到，可能比目標多充一些），還原時照原本的值。編輯視窗與電源頁那一列
    會寫出實際的值，例如「驅動只支援 80% 與 100%，保養上限實際為 80%」；保養上限的選單一定包含你設定的
    值（不被支援時寫成「85%（實際 80%）」）。選項在排程進行中變少時重新取值並記在紀錄檔。
- 狀態：電源頁顯示「等待開始・05:57 開始」「準備充電」「充電中・預計 07:52 到 100%」「已準備好」
  「可能趕不上：只能充到 88%」「暫停（系統）」（上限已經是目標但系統沒在充）或「等待接上電源」。
  充好時與可能趕不上時各通知一次（每一輪只一次，重新開啟看板也不重複）。
- 你自己調整優先：在排程進行中拖動充電上限滑桿、切換「開機與喚醒後保留」，或用其他程式改了
  充電上限，排程就結束，不會改回去。例外是剛從睡眠喚醒時：「開機與喚醒後保留」的服務會把上限改回
  你保留的值，喚醒後 30 秒內第一次的改變視為這個服務，排程繼續並改回排程的上限。
  寫入失敗（例如需要密碼但沒有人輸入）時 1 分鐘後重試（時鐘往回調時不會等更久）。
- 取消：編輯視窗的「取消排程並還原為 N%」。
- 睡眠時（設定 → 充電，或編輯視窗）：
  - 準備優先（預設）：即將睡眠時還在等待，就先把上限提高到目標，在睡眠中充好（可能比預定時間早充滿）。
  - 精準喚醒（需要喚醒元件）：在該開始充電前一分鐘以 RTC 鬧鐘叫醒電腦提高上限。需要 .deb 或
    原始碼安裝的喚醒元件，而且必須先「允許無人時自動調整」；做不到時睡眠前改用準備優先，電源頁說明原因。
    硬體時鐘存本地時間（與 Windows 雙系統）的電腦無法使用。部分電腦關機後也會在鬧鐘的時間開機：
    看板在關機前會取消它（看板沒有執行時做不到）。
  - 有排程時，看板向 logind 要求在即將睡眠時延後最多 4 秒，讓它把上限寫好再睡；沒有排程時不延後。
    限制：你正在調整滑桿、還有別的寫入，或距離上次寫入不到 10 秒時，睡眠前不會提高（小程式會拒絕，
    也等不了）；4 秒內寫不完時系統照樣睡。這些情況都記在紀錄檔，喚醒後再判斷：已經到了開始時間就
    提高，還沒到就照常等待（準備優先在下一次睡眠前會再試一次）。

### 允許無人時自動調整

排程常在你不在電腦前時（例如半夜）提高或還原上限；沒有允許時，這些調整需要管理員密碼，會因為
沒有人輸入而失敗。開啟「允許無人時自動調整」（編輯視窗或「設定 → 充電」，需要輸入一次管理員密碼）後：

- 只限你自己的帳號，而且只在這台電腦登入、正在使用時（不是遠端、不是被切換到背景的工作階段）。
- 只允許兩件事：把充電上限改成 50–100% 的值，以及設定或取消 60 秒後到 7 天內的喚醒時間；
  命令必須與小程式接受的寫法完全相同。開關「開機與喚醒後保留」、CPU 功耗取樣、安裝更新等
  其他管理員動作仍然每次要密碼。
- 做法是在 /etc/polkit-1/rules.d/49-system-device-monitor.rules 寫入一個只給你的 polkit 規則
  （詳見 docs/SECURITY.md「無人授權」）。你的帳號底下的其他程式在你使用電腦時也能做這兩件事；
  不需要時請關閉。
- 撤銷：關閉同一個開關（也需要管理員密碼），或直接執行
  `pkexec /usr/libexec/system-device-monitor/sdm-unattended revoke`
  （原始碼安裝換成 /usr/local/libexec/…）；移除套件或執行
  install.py --system-components remove 時也會刪除這個規則。
- 刪除帳號前請先關閉：規則以帳號名稱比對，之後以同一個名稱建立的新帳號會沿用它。
  `pkexec /usr/libexec/system-device-monitor/sdm-unattended status` 顯示
  `"account_changed":true` 時就是這種情況，請執行上面的 revoke。

### 紀錄與查詢

- 每次狀態改變、寫入的上限與讀回的結果、喚醒排程都記在
  ~/.local/state/system-device-monitor/charging-plan.log（只在這台電腦，超過 256 KB 時只留後半）；
  「設定 → 充電」有「開啟紀錄檔」。排程本身存在 ~/.local/share/system-device-monitor/charging-plan.json
  （0600；無法解讀時另存 .bak 備份後從沒有排程開始）。
- 不開視窗查詢（不載入 GTK、不寫任何檔案）：

      system-device-monitor --charging-plan-status

  印出 JSON：排程、目前的階段、下一次提高上限與喚醒的時間，以及紀錄檔最後 20 行。
- 喚醒小程式也可以直接執行（.deb 的路徑）：

      pkexec /usr/libexec/system-device-monitor/sdm-wake status
      pkexec /usr/libexec/system-device-monitor/sdm-unattended status

  結束碼與其他小程式相同（0、2、3、4）；sdm-wake 不會改動別的程式設定的鬧鐘。

## 通知

提醒由桌面的通知服務（GNOME 等，經由 libnotify）顯示，點通知會開啟相關的頁面
（電池與不斷電系統開「電源」，周邊設備開「連線設備」）。

| 提醒 | 何時通知 | 何時會再通知 |
|---|---|---|
| 電量偏低（筆電） | 正在放電且電量降到門檻以下（預設 20%，5%–50%）；接著電源但充電器功率不足、電量仍在下降時也會提醒 | 接上電源（開始充電）或電量回到門檻＋2% 以上之後 |
| 充電完成（筆電） | 這次接上電源後看過「充電中」，且電量達到門檻（預設 100%，80%–100%）或已達充電上限 | 拔掉電源，或電量低於 `min(門檻, 充電上限) − 5%` 之後 |
| 周邊設備電量偏低 | 電量降到這台設備的門檻以下（預設 20%）；只回報電量等級的設備在等級變成低電量或極低電量時 | 電量回到門檻＋2% 以上（等級回到正常以上），或門檻改成「不通知」之後 |
| 不斷電系統改用電池供電（緊急） | 連續兩次取樣都在用電池；內文有電量、負載瓦數與預估可用時間 | 恢復市電之後 |
| 已恢復市電 | 送出過「改用電池供電」之後恢復市電 | — |
| 不斷電系統電量偏低（緊急） | 確認停電後電量降到門檻以下（預設 50%，10%–90%） | 電量回到門檻＋2% 以上之後 |
| 不斷電系統通訊中斷 | 通訊曾經正常，之後 apcupsd 回報 COMMLOST | 通訊恢復之後 |

- 門檻在「設定 → 通知」（筆電電池與不斷電系統）與「設定 → 周邊設備」調整；周邊設備也可以在
  「連線設備」頁每台設備右邊的鈴鐺選擇（劃掉的鈴鐺是「不通知」）。關閉的提醒照樣記錄狀態，
  之後再打開不會立刻補發。筆電的低電量門檻也決定頂端列電池圖示何時變紅。
- 啟動後與睡眠喚醒後（兩次取樣相隔超過 2 分鐘，含睡眠時間）的第一次取樣只記錄狀態，所以登入時
  不會跳出「充電完成」，啟動時已經在停電也不會通知這次停電。記錄時沿用遲滯：電量仍在重新啟用的
  區間內（例如低電量門檻 20% 時的 21–22%）就維持「已通知」，喚醒後不會再通知一次。
- 同一種提醒（周邊設備為同一台設備）每分鐘最多一則（睡著的時間也算在內）；期間內再發生的只保留
  最新的一則，時間到才顯示。已經過時的不再顯示：喚醒時丟掉所有等待中的提醒；不再放電時丟掉等待中的
  低電量、拔掉電源時丟掉等待中的充飽；恢復市電時，還沒顯示過的「改用電池供電」連同「已恢復市電」
  一起不顯示。
- 送出失敗（例如登入時通知服務還沒啟動）不算送過，30 秒後再試，同一則最多 5 次。
- libnotify 送出時要等通知服務回應，介面在這段時間不會動：看板每次主迴圈最多送一則，一次超過
  2 秒就暫停送出 60 秒（之後再試）。通知服務完全沒有回應時，第一則最多可能讓介面停住約 25 秒
  （D-Bus 的預設逾時）。
- 周邊設備依系統回報的識別碼區分，設定檔只存加了 salt 的雜湊（見隱私說明）；設備斷線後重新連上
  視為新設備，仍低於門檻會再通知一次。識別碼改變（例如重新配對）時門檻回到預設的 20%。
  最多記 64 台設備的門檻，超過時先丟目前看不到的設備（最舊的先）。門檻無法儲存時，
  「設定 → 周邊設備」與鈴鐺的提示會寫出原因，選項恢復成原本的值。
- 設備清單有讀取錯誤（例如藍牙服務讀取失敗）時，不把清單中沒有的設備當成斷線。某個來源一直失敗時
  （例如這台電腦沒有藍牙），斷線的設備永遠不會被移除：重新連上時不會再通知，要等電量回到門檻＋2%
  以上才重新啟用。
- 「設定 → 通知 → 傳送測試通知」立即送出一則測試通知（不受每分鐘一則的限制）。找不到通知服務時，
  按鈕下方會說明原因。
- 從終端機確認通知功能：看板執行中時執行下列指令，它請看板送出測試通知後立即結束，
  自己不送通知、不開視窗。看板每 10 秒最多處理一次這個要求。結束碼：0 要求已送出、
  1 看板沒有執行（或版本太舊）、2 連不到桌面工作階段的匯流排。

      system-device-monitor --test-notification

- --smoke-test 與 --preview 完全不送出通知（設定視窗的按鈕停用並說明原因）。

## 示範模式（--preview）

    system-device-monitor --preview laptop-battery

可選 laptop-battery（用電池）、laptop-charging（充電中、到上限 80%）、
laptop-limit（已達上限）與 desktop（桌機）。示範模式：
- 只用記憶體中的示範資料與合成的 7 天歷史；不讀寫設定、歷史、裝置別名或自動啟動。
- 使用另一個應用程式代號，不會把請求交給正在執行的看板，也不建立頂端列圖示；
  關閉視窗就結束，也因此不能搭配 --background。總覽頁與系統監控頁的處理器、溫度、風扇、
  App 排行、記憶體、網路與磁碟也都是示範值（位址只用文件範例網段 192.0.2.0/24），
  截圖不含這台電腦的資料。
- 設定視窗可以操作，變更只在這次執行套用，不寫入任何設定檔；「電源模式」只在記憶體中切換，
  不會改到這台電腦的電源模式。不送出任何通知。換程式圖示顏色只改視窗圖示，不寫入圖示主題。
- 筆電示範的充電上限滑桿使用示範值（上限 80%）：拖動與「開機與喚醒後保留」只在記憶體中改變，
  狀態列顯示「示範模式不會寫入」，不會執行 pkexec 或任何管理員元件，也不偵測衝突的程式。
- 夥伴與桌面寵物使用示範資料；不讀自己的照片（「我的照片」改畫內建的貓咪大頭照），
  也不讀寫桌面寵物的位置，截圖不會出現自己的照片。
- 搭配 --smoke-test --capture 時必須指定 --output-dir，截圖與 smoke.json 只寫到那裡。

## 回報筆電問題（--dump）

回報筆電電池相關的問題時，請貼上這個指令的輸出：

    system-device-monitor --dump

它只印出一個 JSON 物件後結束，不開視窗、不寫任何檔案，內容包含：
模式（laptop／desktop）、每個 power_supply 項目的名稱、類型、scope、狀態與
「可讀的屬性名稱」（不含數值）、是否有充電門檻、變壓器類型與是否接上、
是否有不斷電系統、顯示卡名稱、UPower 與電源模式服務是否可用、程式版本與機殼類型代碼。
不含序號、UUID、MAC 位址、IP、主機名稱或家目錄與掛載路徑；名稱裡像 MAC 位址的部分會改成 xx。
貼上前仍請自行看過一次。

## Logitech 電量與滑鼠設定

Logitech G HUB 沒有官方 Linux 版；[Solaar](https://github.com/pwr-Solaar/Solaar) 查看電量與設定，
[Piper](https://github.com/libratbag/piper) 管理滑鼠設定，兩者都是選用的：

    sudo apt install solaar piper ratbagd

原始碼依賴腳本也可使用 ./install-dependencies.sh --logitech 一併安裝。
安裝後重新插拔 Logitech 接收器，讓套件附帶的 udev 權限規則生效；
看板和 Solaar 都以一般使用者執行。

- Solaar：從應用程式選單開啟，查看裝置電量與支援的設定。
- Piper：從應用程式選單開啟，查看 DPI、按鍵及設定檔。可用功能依型號而異。
- 看板：重新啟動後自動偵測 Solaar，無須讓 Solaar 圖形介面常駐。
  套件可能加入 Solaar 登入啟動項目；若只使用看板電量，可在啟動應用程式中停用它。

目前驗證的電量協定為 G304／G305（HID++ 配對裝置 ID 4074）的 BATTERY STATUS。
看板每 60 秒查詢一次，單次最多等待 15 秒，顯示資料來源、更新時間及下一級電量。
「約 50%（分段回報）」代表裝置給出的級距，不是連續精確電量。
只有等級時仍保留等級；電池狀態協定的 0／未知不會被誤顯示為 0%。

讀不到、逾時、移除或核心回報離線時，停止使用先前的數字；
快取最長 90 秒。裝置狀態通常在下一次 5 秒更新時反映，
重新連線後等下一次 Solaar 查詢才恢復數字。

Piper 可能辨識滑鼠，卻對作用中的設定檔或 DPI／回報率呈現不一致讀值。
遇到此情況，先核對 Solaar 與裝置目前行為，再使用 Piper 的 Apply；
看板只查電量，不會修改 DPI、按鍵、配對或韌體。

自行診斷可執行 solaar show。其完整輸出可能含裝置序號、配對識別碼及設定，
請只分享去識別化的電量摘要，不要直接上傳原始輸出。

## 裝置名稱覆寫

在 XDG 設定目錄建立 device-aliases.json。鍵值為
「USB vendor:product|manufacturer|product name」，必須完全符合系統描述。
以下全為虛構範例，請使用本機描述替換：

    {
      "1234:5678|Example Vendor|Example Receiver": {
        "name": "我的無線鍵盤接收器",
        "status": "接收器已連接 · 鍵盤無線狀態未知",
        "battery": "有電池 · 電量未回報"
      }
    }

重啟應用程式後生效。此檔案只留在本機，不應提交到 GitHub。
別名只影響名稱與說明，不會讓沒有回報電量的鍵盤等設備取得電量。
缺少或格式錯誤的覆寫會退回裝置原始名稱。

## 更新

「設定 → 更新」顯示目前版本與安裝方式（.deb 套件或原始碼資料夾）：

- 自動檢查更新（預設開啟）：看板啟動 15 秒後與之後每 6 小時看一次，但距離上次成功的檢查超過
  24 小時才連到 GitHub（api.github.com）。自動檢查只看正式版，同一個版本只通知一次
  （「有新版本時通知」可以另外關閉）；點通知開啟「設定 → 更新」。檢查失敗時不顯示錯誤，下次再試。
- 立即檢查：馬上確認一次，也列出比較新的測試版（Beta，不會自動通知）；失敗時顯示原因。
- 有新版本時列出版本號、更新內容摘要（純文字、最多 12 行）與「在 GitHub 查看這個版本」。
- .deb 安裝：按「安裝更新」後，看板在背景下載 SHA256SUMS 與它的簽章 SHA256SUMS.sig，先以內建的
  維護者公鑰驗證簽章，再下載 .deb 並比對檢查碼、確認套件名稱與版本，接著要求管理員密碼
  （每次都要），由管理員小程式再驗證一次後以 apt-get 安裝，完成後看板自動重新啟動
  （原本在背景執行時仍在背景）。任何一步失敗都不會安裝，設定頁顯示原因。
- 0.2.0 以前的版本沒有一鍵更新，升級到 0.3.0 請依下方手動更新一次。自行建置、沒有內建公鑰的版本
  「安裝更新」維持停用，設定頁顯示「未設定簽章金鑰：這個版本無法一鍵更新，請到 GitHub 下載新版。」
- 原始碼資料夾：顯示可以複製的 git -C <資料夾> pull --ff-only 指令；完成後從頂端列選單「退出」
  再重新開啟看板。更新紀錄寫到啟動器有變更時，另外執行一次 /usr/bin/python3 install.py；
  管理員元件有變更時（「設定 → 管理員功能」顯示需要重新安裝）再執行顯示的
  install.py --system-components install 指令。

也可以手動更新。原始碼版本，先從頂端列退出，再執行：

    git pull --ff-only
    /usr/bin/python3 install.py
    ~/.local/bin/system-device-monitor

.deb 版本從 Releases 下載 .deb 與 SHA256SUMS（有 SHA256SUMS.sig 時一併下載），確認檢查碼後以
sudo apt install ./新版本.deb 更新，再重啟應用程式。
兩種方式都保留設定、歷史及自動啟動設定；原始碼安裝過管理員元件時，見「管理員元件」的重新安裝。

## 移除

.deb 安裝請先在「設定 → 一般」關閉登入自啟（apt 不會刪除家目錄裡的自啟檔），再使用頂端列「退出」。

原始碼安裝（安裝過管理員元件時先移除它；這也會取消智慧充電排定的喚醒並刪除無人授權的規則）：

    /usr/bin/python3 -B install.py --system-components remove
    /usr/bin/python3 install.py --uninstall

--uninstall 刪除啟動器、應用程式選單的項目、登入自啟，以及本程式寫入 ~/.local/share/icons 的程式圖示
（只刪記錄中、內容沒有被改過的檔案）；原始碼資料夾本身留著。

.deb 安裝（移除時一併停用服務、取消智慧充電排定的喚醒、刪除無人授權的規則與保留的充電上限）：

    sudo apt remove system-device-monitor
    sudo apt purge system-device-monitor

purge 另外刪除一鍵更新的執行鎖，並再確認一次上面的系統檔案都已刪除。apt 不會代替使用者刪除
家目錄內容：.deb 安裝時若選過其他圖示顏色，移除前先在「設定 → 外觀」改回薄荷綠，或自行刪除
~/.local/share/icons/hicolor 底下的 system-device-monitor.png。

兩種方式都保留設定、歷史與日誌；要完全清除時，刪除下一節列出的 system-device-monitor 資料夾。

## 檔案位置

設定與資料遵循 XDG 路徑（下面是預設位置），只存在這台電腦：

- 設定：~/.config/system-device-monitor/settings.json（舊版五個頂端列項目）與同目錄的
  preferences.json（其他設定），以及選用的 device-aliases.json（裝置名稱覆寫）。
- 登入自啟：~/.config/autostart/system-device-monitor.desktop。
- 資料：~/.local/share/system-device-monitor/ 底下的 history.json（耗電與電量歷史）、
  charging-plan.json（智慧充電的排程）、companion-photo.png（我的照片）與 app-icon.json
  （本程式寫入的程式圖示）。
- 狀態：~/.local/state/system-device-monitor/ 底下的 state.json（最後一頁）、pet.json
  （桌面寵物的位置）、charging-plan.log（智慧充電的紀錄）、update-state.json（上次檢查更新的時間）
  與 cpu-calibration.json（APU 校正是否已確認）。
- 日誌：~/.cache/system-device-monitor/app.log（登入自啟與從應用程式選單啟動時）。
- 頂端列的耗電圖示：$XDG_RUNTIME_DIR/system-device-monitor/icons/（登出就清除）。
- 換色的程式圖示：~/.local/share/icons/hicolor 底下 128x128 與 512x512 的 apps/system-device-monitor.png。
- 系統檔案（管理員元件與它們的狀態）見 [SECURITY.md](SECURITY.md#安裝的檔案)。

## 資料來源與限制

- 整機耗電：已經設定好的 APC 不斷電系統（apcupsd／apcaccess）。看板只讀取狀態，不安裝或修改
  寄信、關機門檻及 SMTP 憑證。
- CPU：型號與核心數自動讀取；CPU 溫度支援 k10temp 的 Tctl／Tdie 與 coretemp 的 Package 溫度，
  其他感測器列在「風扇與溫度」；主機板沒有回報風扇時會註明。
- 顯示卡：NVIDIA 的使用率、顯示記憶體、耗電與風扇百分比來自 nvidia-smi，AMD 讀 sysfs。
  總覽卡片顯示第一張 NVIDIA（沒有時為 AMD 獨顯），「CPU／GPU」頁列出每一張。
- 溫度放在對應裝置名稱後（例如「裝置 · 型號 · 容量 · 溫度」），依 sysfs 的硬體路徑配對；
  沒有 hwmon 的硬碟改用磁碟服務回報的 SMART 溫度，兩者都沒有時標示「溫度未回報」。
- 網速摘要加總已連線的實體介面，虛擬介面另外列出。
- 周邊設備：USB 與 BlueZ 確認已連線的藍牙設備；接收器存在不表示無線端一定開機，沒有資料時標示
  未知或未回報。有百分比就顯示百分比，只回報等級時顯示「電量等級：正常」等文字，不換成虛構的百分比。

## 疑難排解

- 沒有頂端列：確認 GNOME AppIndicator 擴充功能已啟用；必要時登出再登入。
- 找不到 gi 或 Cairo：使用 /usr/bin/python3，並重跑相依套件安裝腳本。
- 安裝更新時顯示 apt-get 超過時限：套件可能只裝了一半，請在終端機執行 sudo dpkg --configure -a，
  完成後再按一次「安裝更新」。
- GPU 未回報：確認 NVIDIA 驅動與 nvidia-smi 可用；不影響其他功能。
  看板執行期間會常駐一個 nvidia-smi 程序（跟著更新頻率輸出，最快每 2 秒一次），結束時一併停止；
  它意外結束時會在 1 秒到 60 秒之間逐次加倍等待後重新啟動。
- 耗電顯示「無法取得整機耗電」：表示讀不到不斷電系統，請確認 apcaccess status 可用。
- UPS 未回報：確認原有 apcupsd 已設定並可執行 apcaccess status。
- 硬碟溫度未回報：先讀 hwmon，沒有時用磁碟服務的 SMART 溫度；多數 USB 外接盒兩者都沒有，
  不會用其他硬碟的溫度代替。SMART 溫度要在總覽或磁碟頁開過之後才會出現。
- App 排行是空的：需要 cgroup v2 與 systemd 使用者工作階段（Ubuntu 預設）。
- 電量只有等級：這是目前資料來源的精度，並不是宣稱裝置沒有電池。
- 藍牙或 UPower 暫時無法取得：USB 與系統監看仍繼續，下一次更新會重試。
- 沒有收到通知：先用「設定 → 通知 → 傳送測試通知」或 system-device-monitor --test-notification
  確認；設定視窗說明找不到通知服務時，表示目前的桌面沒有通知服務。GNOME 開啟「勿擾」時只會跳出
  緊急通知（不斷電系統改用電池與電量低），其他提醒仍會留在通知清單中。
- 開啟 CPU 功耗取樣時顯示「未授權」：取消了授權或密碼不正確；從遠端或非作用中的工作階段
  一律不允許。從登入自動啟動的看板若一直顯示未授權，請從應用程式選單重新開啟看板再試。
- 充電上限顯示「未套用」：取消授權或密碼錯誤時重新拖動一次；顯示電池不接受某個值時改選建議的值；
  其他原因可用 pkexec …/sdm-charge-limit status 查看目前的門檻，系統日誌（journalctl -t sdm-charge-limit）
  只記錄動作與結果。
- 開機或喚醒後上限又變回去：開啟「開機與喚醒後保留」；仍然變回去時檢查滑桿下方是否有 TLP、asusd
  或「保護電池健康」的提醒，並用 systemctl status system-device-monitor-charge-limit.service 查看
  最後一次重新套用的結果。
- 開啟了但拆解沒有 CPU：這台電腦沒有 RAPL（/sys/class/powercap/intel-rapl:0），
  或服務回報讀取失敗；可用 systemctl status system-device-monitor-cpu-power.service 查看。

## 本機診斷

先退出正在執行的實例，以免單一實例機制把請求交給舊程序：

    system-device-monitor --smoke-test --output-dir /tmp/monitor-check

約 25 秒後結束。只產生簡短的 smoke.json（含依序顯示過的頁面與設定視窗的分類名稱），
不列硬體、主機名稱或裝置識別碼。耗電歷史只存在記憶體，不讀也不寫 history.json；不送出通知。
應用程式必須在有顯示器及 D-Bus 的桌面工作階段執行。
如需自行檢視畫面，可額外加 --capture，只截取應用程式視窗，
不截整個桌面。截圖可能含私人裝置名稱或掛載路徑，勿直接上傳。
